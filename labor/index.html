Policies

Uses the current stations, machines, walking time and distributions. When n varies, every worker has speed 1.0 and the WIP rule above is kept as it is (with a CONWIP cap w < n only w workers can be busy; with no cap, zones and job dropping get w = 2n, otherwise their WIP never settles). When w varies, the current workers are used.

Model and assumptions

What is simulated

  • A serial line of N stations. Station k has mk machines (workplaces) and a work content STk per job.
  • Every operation needs one worker and one machine for its whole duration. A worker with speed v completes STk in STk/v, so the machines run at the pace of the worker.
  • WIP w counts every job in the system, including those waiting before the first station; LT is measured from entry in the system to exit, so WIP = TR · LT (Little).
  • Buffers between stations have unlimited capacity: blocking comes from busy machines and from the workers themselves.
  • Exact event-driven simulation: with deterministic times the results match the formulas to the last digit.

Formulas used (slides 91–98)

  • TR ≤ min( n/VAT , TRb ) labor or machines
  • TR = n/VAT labor capacity, THmax = n/T0
  • LTworker = VAT once a worker takes the job
  • LTwip = w/TR = (w/n)·VAT w ≥ n, Little
  • LTqueue = (w−n)/n · VAT wait for a free worker
  • TR = w/VAT w < n, only w workers busy

Things to try in class

  • Pizza shop: go from 2 to 4 workers and check LT = 80 → 40 min (−50%).
  • Same line, tied workers vs bucket brigade with equal speeds: identical results, only the identity of the worker changes.
  • Bucket brigade: order slow → fast, then fast → slow, and watch the space–time diagram.
  • Bottleneck at the end: tied workers spend a lot of time blocked. Try job dropping without a cap, then with a cap.
  • Exponential times with one machine per station: blocking pulls TR below n/VAT.
